🐞 What QA Adds in Jira

  • Clear defect title
  • Environment / build
  • Steps to reproduce
  • Expected result
  • Actual result
  • Severity and priority
  • Screenshot / video
  • Logs or API evidence where applicable
  • Related test case / requirement

👨‍💻 Who Owns What?

  • QA: Finds, documents and verifies the defect.
  • Developer: Investigates and fixes the defect.
  • QA: Retests after developer marks it ready.
  • QA: Reopens it if the issue still exists.
  • Developer: Investigates the reopened defect again.
05 • EXECUTION DETAILS

What Exactly Does QA Do?

A practical breakdown for every major testing activity.

📋 Requirement Review

  • Read user story and acceptance criteria.
  • Identify missing scenarios.
  • Ask questions before development/testing.
  • Identify business risks.
Tool: Jira / Confluence
Action: Review documentation and record questions.

🧪 Manual Functional Testing

  • Execute test cases.
  • Compare actual vs expected result.
  • Test positive and negative flows.
  • Validate UI and business rules.
Tool: TestRail / Zephyr / Jira
Action: Execute cases and record results.

🔌 API Testing

  • Validate request method.
  • Validate status code.
  • Validate response data.
  • Test authorization.
  • Test invalid input.
Tool: Postman
Action: Send API requests and validate responses.

🤖 Automation

  • Identify stable repetitive scenarios.
  • Create automated test.
  • Execute test suite.
  • Analyze failed tests.
  • Maintain scripts after application changes.
Tools: Playwright / Selenium / Katalon / Tosca / mabl
Action: Automate repeatable UI/business workflows.

🌐 Compatibility Testing

  • Test supported browsers.
  • Test responsive layouts.
  • Check mobile/tablet/desktop.
  • Identify browser-specific defects.
Tool: BrowserStack
Action: Run application on multiple browser/device combinations.

⚡ Performance Testing

  • Simulate users.
  • Measure response time.
  • Observe throughput.
  • Identify performance bottlenecks.
Tool: JMeter
Action: Execute load/performance scenarios.
06 • RELEASE GATE

QA Report → Release Decision

Before release, QA communicates the complete testing picture: coverage, executed cases, defects, blockers, automation results, risks, limitations and final testing status.

📊 QA Report Contains

  • Total test cases
  • Passed / Failed / Blocked
  • Defects found
  • Critical / High / Medium / Low
  • Open / Closed defects
  • Regression status
  • Automation results
  • API testing results
  • Compatibility results
  • Performance results if applicable

🚀 Production

  • Verify deployment.
  • Perform production smoke test.
  • Verify critical user journeys.
  • Monitor production issues.
  • Record customer-reported defects.
  • Feed important scenarios back into regression.
